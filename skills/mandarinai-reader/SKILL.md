# mandarinai-reader

把一段素材整理、改写成一篇**供中文学习者阅读的文章**。

素材可以是一条视频（小红书 / B站 / YouTube / 抖音）、一篇文章、一段原始文本，或一个话题。产物是一篇**分级中文文章**：词汇和语法控制在目标水平，中文自然地道，既能读懂，又能学到。

这不是给母语者看的观点文（那是 mandarinai-writes），也不做卡片（生词可交给 mandarinai-flashcard）。纯文本生成，不接数据层——分级和词义由你的判断把控，所以分级标准要稳（见 `references/leveling.md`）。

## 工作流

### Step 1 · 取素材

按输入类型取到干净的素材文本：

- **视频链接**（小红书 / B站 / YouTube / 抖音）→ 用 mandarinai-video-fetch skill 取清洗后的文字稿；该 skill 不可用时直接运行 `bash ~/.agents/skills/mandarinai-video-fetch/scripts/fetch-video.sh "<URL>"`（B站 AI 字幕、小红书需加 `-c chrome`）。
- **文章 / 网页链接** → 抓取正文（Claude Code 用 WebFetch；Codex / Gemini CLI 用内建 fetch 或 curl）。
- **原始文本 / 话题** → 直接用。

**没拿到正文就停**。这是硬规则，不是建议：

- `fetch-video.sh` 的最后一行是 `TRANSCRIPT: <路径>` 才算成功；若是 `AUDIO: <路径>`（无字幕又没有转写后端）或报错，**就地停下**，告诉用户文字稿没取到、原因（缺 `-c chrome` cookies？whisper 后端没起？），让用户处理后再来。
- 网页抓取返回空 / 失败同理。
- **绝不靠视频标题、链接或常识脑补正文**——没有素材就没有文章。给学习者编造内容比不出文章更糟。

取到后，先在心里抓住素材的**核心信息**：它讲了什么、最值得让学习者带走的是什么。整理的是信息，不是逐句翻录——下游要的是一篇文章，不是字幕。

### Step 2 · 定水平

文章必须写在一个明确的目标水平上。

- 用户给了水平（「HSK 4」「中级」）→ 按它写。
- 没给 → **问一句**（Claude Code 用 AskUserQuestion；Codex / Gemini CLI 直接在对话里问）。默认 **HSK 3–4（中级）**。

各级的词汇、语法、句长、篇幅边界见 `references/leveling.md`——动笔前读它，分级才稳。

确认这几项（默认值可直接用）：
- **水平**：HSK 几级 / 初中高
- **篇幅**：默认按水平给（初级 150–300 字，中级 300–600 字，高级 600–1000 字）
- **生词表**：默认带（最有用的学习辅助）；用户说不要就去掉

### Step 3 · 写

整理改写，不是翻译，也不是原文搬运。原则见下「写作原则」。

默认产出结构：

1. **标题**——中文，配拼音
2. **正文**——分级改写后的文章，分段，句子完整自然
3. **生词表**——正文里超出目标水平的词，逐条 `词 — 拼音 — 简明释义`（默认 8–15 个，按篇幅增减）

按需追加（用户要才加，不要默认堆上去）：
- **拼音版正文**——整段或逐句注音，给初级 / 朗读用
- **语法点**——挑 1–3 个本级关键句型，例句来自正文
- **思考题**——2–3 个理解 / 讨论问题
- **英文导读**——一段英文摘要帮助理解大意

### Step 4 · 交付

1. `date "+%Y-%m-%d %H:%M"` 取日期。
2. 从标题提关键词，写入 `~/Documents/mandarin-reading/{YYYYMMDD}-{标题关键词}.md`（用户指定位置则优先）。
3. 文件头：

```
---
title: {标题}
date: {YYYY-MM-DD HH:MM}
level: {HSK n / 初中高}
tags: [mandarinai-reader]
source: {素材来源链接或描述}
---
```

4. 报告路径、目标水平、字数、生词数。
5. 若生词表里有词，可提示：要做成闪卡就接 mandarinai-flashcard。

## 写作原则

给学习者写，和给母语者写不是一回事。核心是**可理解输入**：内容稍微够一够能懂，词汇语法卡在目标水平上下。

- **忠于素材**：信息、事实、人名、数据照素材来，不编造。素材里没有的别加。不确定的内容宁可不写。
- **整理，不照搬**：口播的啰嗦、跑题、重复，整理成有结构的文章。保留素材的核心和有意思的细节，砍掉水分。
- **控制词汇**：尽量用目标水平及以下的词。必须用更高级的词（专有名词、关键概念）→ 放进生词表，正文里别堆。
- **控制语法**：句型不超过目标水平。长句拆短，少用嵌套从句和生僻连词。初级尤其要短句。
- **自然地道**：是给人读的中文，不是教科书例句的拼接。该用的连接、过渡、语气照常用，只是控制在水平内。翻译腔免疫——别让它读起来像从英文翻过来的。
- **完整成篇**：有头有尾，段落之间有逻辑。不是要点罗列，是一篇能从头读到尾的文章。
- **一篇一个重点**：素材若发散，挑最值得学习者带走的一条主线写，别面面俱到。

## 约束

- 分级以 `references/leveling.md` 为准；拿不准一个词 / 句型是否超纲，宁可降级或放进生词表。
- 释义、拼音要准——错一个字误导一个学生。拼音用标准声调标注。
- 不接数据层、不调 API：纯文本生成。
- 生成的文章写到 `~/Documents/mandarin-reading/` 或用户指定位置，不要写进 skill 目录。
- 不绕过平台付费 / 登录限制：取视频素材时 cookies 只用于用户自己有权访问的内容。

## 运行环境适配

- **Claude Code**：用 WebFetch 抓网页、AskUserQuestion 问水平、Read/Write/Bash 处理文件。
- **Codex / Gemini CLI**：在对话里问水平；抓取用内建 fetch 或 curl；不要假设 Claude 专用工具存在。
- **Gemini CLI 沙箱**：Gemini 默认只能读写工作区目录。`~/Documents/mandarin-reading/`、`/tmp/video-fetch/` 都在工作区外——启动时用 `--include-directories ~/Documents/mandarin-reading,/tmp/video-fetch`，或让用户指定一个工作区内的输出路径。视频转写需要 `WHISPER_BASE_URL` 等环境变量已 export 给 CLI 进程。
